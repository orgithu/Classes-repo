

#  Шилэн Кабелийн Сүлжээний Загварчлал ба Симуляцийн Систем бүтээх төсөл 

## 1. Сүлжээний Бизнес ба Дэд Бүтцийн Шаардлага (Network Domain Requirements)

### 1.1 Физик ба Газарзүйн Шаардлага

* **Бүс нутгийн хамралт:** Монгол улсын аймгийн төвүүд болон гол зангилаа 22 хотыг (Улаанбаатар, Дархан, Эрдэнэт, Сэлэнгэ, Хэнтий, Сайншанд гэх мэт) бүрэн холбосон сүлжээ байна.
* **Кабелийн трасс:** Шилэн кабелийг авто болон төмөр замын дагуу татах боломжтой замаар төлөвлөж, трассын урт км-ийг бодит замын зайд үндэслэн тооцно(optional).
* **Газарзүйн эрсдэл:** Уулархаг болон говийн бүсийн байгалийн эрсдэлтэй (үер, нуранги, шороон шуурга) замуудыг дайран гарах замын уртыг боломжит бага түвшинд барина(optional).

### 1.2 Сүлжээний Архитектур ба Бэлэн Байдал

* **1-Fault Tolerance:** Аль нэг 1 магистраль трасс (ирмэг) тасрахад аль ч аймаг/хот сүлжээнээс тасрахгүй, нөөц замаар Redundant Path үргэлжлүүлэн ажиллах ёстой.
* **Bridge-less Топологи:** Сүлжээнд ганц цэгийн гэмтлээр Single Point of Failure бүхэлд нь тасалдаг **Bridge (критик холбоос)** огт байхгүй буюу $2-Edge-Connected$ төлөвийг хангана.

### 1.3 Эдийн Засаг ба Хөрөнгө Оруулалт

* **Төсвийн хязгаарлалт (Cost Minimization):** Шилэн кабель шинээр татах зардлыг боломжит хамгийн бага түвшинд барина.
* **CAPEX Optimization:** 100% Full Mesh-ээс зайсхийн, **MST + Хамгийн бага зардлаар цагираг үүсгэх (2-Edge Addition)** стратеги баримтална.
* **Cost vs Security Trade-off:** Ердөө 15–20%(or more) нэмэлт кабель тавихад сүлжээг бүхэлд нь 2-Edge-Connected болгох оновчтой бүтцийг сонгоно.

### 1.4 Дамжуулах Чадал ба Хоцролт

* **Хоцролт (Latency):** Сүлжээний хамгийн алслагдсан хоёр зангилааны хоорондох дохио дамжих хугацаа (Round-Trip Time) нь **50ms**-ээс бага байна.
* **Traffic Rerouting:** Гэмтэл гарахад урсгалыг нөөц зам руу чиглүүлэнэ.

## 2. Системийн Програм Хангамжийн Шаардлага (System Software Requirements)

### 2.1 Функциональ Шаардлага (Functional Requirements)

#### 2.1.1 Өгөгдөл ба Графын Удирдлага

* **FR-1.1:** Систем нь Монгол улсын 22 цэгийн газарзүйн солбицол ($Latitude, Longitude$) болон хотуудын хоорондох замын уртыг км оруулж граф үүсгэнэ.
* **FR-1.2:** Сүлжээний зангилаа Node ба ирмэг Edge-ийг нэмэх, хасах, засах функцтэй байна.

#### 2.1.2 Топологи Тооцоолол ба Алгоритмууд

* **FR-2.1 (MST):** Prim эсвэл Kruskal-ийн алгоритмаар хамгийн бага зардлаар холбох Модон сүлжээг (MST) тооцоолж, нийт замын уртыг гаргана.
* **FR-2.2 (Bridge Detection):** Граф дахь бүх **Bridge (Критик замууд)**-ийг Tarjan-ий алгоритмаар автоматаар илрүүлж жагсаана.
* **FR-2.3 (2-Edge-Connectivity):** MST дээр суурилан хамгийн бага зардлаар сүлжээг 2-Edge-Connected төлөвт оруулах нэмэлт ирмэгүүдийг сонгоно.

#### 2.1.3 Failure Simulation

* **FR-3.1 (Cut-Edge Test):** Хэрэглэгчийн сонгосон кабель тасрах үед сүлжээ холбоотой хэвээр үлдсэн үү, эсвэл салж тусгаарлагдсан уу гэдгийг шалгана.
* **FR-3.2 (Impact Analysis):** Кабель тасрахад сүлжээнээс салж буй аймгуудыг жагсаан мэдээлнэ.

#### 2.1.4 Визуал Дүрслэл ба Тайлан

* **FR-4.1:** Сүлжээний топологиудыг газарзүйн карт дээр (OpenStreetMap) ялгаатай өнгөөр (MST = Улаан, 2-Edge = Цэнхэр, Full Mesh = Ногоон) дүрсэлнэ.

### 2.2 Функциональ Бус Шаардлага (Non-Functional Requirements)

* **Гүйцэтгэл (Performance):** Графын тооцооллууд болон API-ийн хариу үйлдэл **1 секундээс бага** хугацаанд бодогдоно.
* **Ашиглахад хялбар байдал (Usability):** Газрын зураг дээр шууд клик хийж кабель/зангилааны мэдээллийг харах интерактив боломжтой байна.
* **Өргөтгөх боломж (Scalability):** Ирээдүйд шинээр зангилаа нэмэхэд алгоритмууд өөрчлөлтгүй шууд ажиллах модульчлагдсан бүтэцтэй байна.
* **Нийцтэй байдал (Compatibility):** Веб браузерууд (Chrome, Firefox, Edge) дээр нэмэлт плагин шаардахгүйгээр ажиллана.

### 2.3 Технологийн Стек (Tech Stack)

## 3. Ажлын Нарийвчилсан Төлөвлөгөө (Work Plan & Workflow Guide)

### Үе шат 1: Өгөгдөл Цуглуулах ба Сүлжээний Загварчлал (Data Modeling)

1. **Зангилаанууд (Nodes):**
* Монгол улсын 22 зангилаа цэгийн газарзүйн солбицол ($Latitude, Longitude$)-ыг цуглуулах.


2. **Ирмэгүүд ба Жигнүүр (Edges & Weights):**
* Хотууд хоорондын авто замын бодит зайн өгөгдлийг ($км$)-ээр оруулж матрицыг бэлдэх.


3. **Графын бүтэц үүсгэх:**
* Чиглэлгүй жигнэсэн граф (Undirected\ Weighted\ Graph) болгон Python-ы `NetworkX` дээр бэлтгэх.



### Үе шат 2: Математик ба Алгоритмчлал (Backend Logic)

1. **MST (Minimum Spanning Tree):**
* `nx.minimum_spanning_tree(G, algorithm='prim')` - Хамгийн бага зардлаар бүх зангилааг холбох суурь сүлжээ.


2. **Bridge Detection (Критик замуудыг илрүүлэх):**
* `nx.bridges(G)` - Тасрахад сүлжээг тусгаарлах аюултай кабелийн замуудыг илрүүлэх.


3. **2-Edge-Connected Subgraph Addition (Нөөц зам нэмэх):**
* MST дээр суурилан гүүр (bridge) бүрийг цагирагт оруулах хамгийн бага жинтэй нэмэлт ирмэгүүдийг сонгон нэмж, $2-Edge-Connected$ төлөвт оруулах.


4. **Dynamic Cut-Edge Algorithm:**
* Хэрэглэгчийн сонгосон аль нэг ирмэгийг хасахад `nx.is_connected(G)` ашиглан сүлжээний бүрэн бүтэн байдлыг шалгах.



### Үе шат 3: Flask REST API хөгжүүлэлт (Backend)

1. **Серверийн тохиргоо:**
* `Flask` ба `flask-cors` суулган REST API ажиллуулна.


2. **Endpoint-ууд зохиомжлох:**
* `GET /api/network/topologies` — MST, 2-Edge, Full Mesh топологийн өгөгдлийг JSON хэлбэрээр буцаах.
* `POST /api/network/simulate-cut` — Сонгосон кабелийг тасалж, үлдсэн сүлжээний төлөвийг мэдээлэх.



### Үе шат 4: React + Leaflet Веб Интерфэйс (Frontend)

1. **Интерактив Карт (React-Leaflet):**
* OpenStreetMap дээр хотуудыг `Marker`, кабелийг `Polyline`-аар зурна.


2. **Топологийн удирдлага:**
* MST (Улаан), 2-Edge-Connected (Цэнхэр), Full Mesh (Ногоон) өнгөөр солин харах товчлуурууд.


3. **Статистик Панель:**
* Нийт замын урт ($км$), Критик холбоос ($Bridge$)-ын тоо, Сүлжээний аюулгүй байдлын төлөвийг ($1-Fault\ Tolerant$) харуулна.



### Үе шат 5: Судалгааны Тайлан ба Дүгнэлт Бичих (Academic/Technical Report)

| Бүлэг | Агуулга |
| --- | --- |
| **1. Удиртгал** | Монгол улсын шилэн кабелийн ач холбогдол, эрсдэл ($Single\ Point\ of\ Failure$). |
| **2. Онолын хэсэг** | Graph Theory, Prim's Algorithm, Bridge Detection (Tarjan's algorithm), 2-Edge-Connectivity. |
| **3. Симуляци ба Төрөл бүрийн Загвар** | MST vs 2-Edge-Connected сүлжээний зардлын ба аюулгүй байдлын харьцуулалт. |
| **4. Үр дүн ба Дүгнэлт** | Хамгийн бага зардлаар 100% 1-fault tolerant сүлжээ үүсгэх боломжийн шийдэл. |
